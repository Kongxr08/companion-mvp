# 小满：本地文字聊天伙伴 MVP

Python + SQLite + 原生网页。Python **3.11 或以上**即可运行，无需 pip、Node.js、数据库服务或前端构建。默认只监听 `127.0.0.1`，供同一台电脑上的一个用户使用。

## 开始使用

Windows 双击 `start.cmd`，保持终端窗口运行，在浏览器打开：

**http://127.0.0.1:8765**

也可以在项目目录执行：

```powershell
python app.py
```

如果端口被占用，可改为 `python app.py --port 8766`，然后打开对应地址。停止时按 Ctrl+C。

未配置模型时，页面明确显示**规则演示模式**。演示模式能验证保存、回忆、纠错、情绪变化和主动消息；它不是自由聊天大模型。

### 接入真实模型

1. 将 `.env.example` 复制为同目录的 `.env`。
2. 填写 `LLM_MODEL` 和服务商所需的 `LLM_API_KEY`。
3. 按服务商协议选择 `LLM_API_STYLE` 与 `LLM_BASE_URL`。
4. 重启后台程序。页面应显示你填入的模型名称，演示横幅消失。

OpenAI 接口示例（模型名请填写你有权使用的文本模型 ID）：

```dotenv
CHAT_MODE=live
LLM_API_STYLE=responses
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=填入可用的模型ID
LLM_API_KEY=填入你的密钥
```

其他兼容 Chat Completions 的服务或本机模型服务：

```dotenv
CHAT_MODE=live
LLM_API_STYLE=chat_completions
LLM_BASE_URL=http://127.0.0.1:1234/v1
LLM_MODEL=本机已加载的模型ID
LLM_API_KEY=
```

这里不附带或自动下载模型。本机模型服务应预先启动；某些本机服务也要求密钥。远程地址必须使用 HTTPS。本地模型与所有兼容接口的行为并不完全一致，可能需要调整 `Provider.complete` 的参数。

真实模式下，服务商会收到近期对话、相关记忆、人格和情绪背景。密钥只在服务器环境中使用，不返回浏览器。OpenAI Responses 请求设置 `store=false`，这不等于服务商完全不保留任何日志；请以服务商的数据政策为准。真实接口错误会显示在页面，不会悄悄降级为演示回复。

## 五分钟验收

1. 发消息：`我叫小林。我喜欢雨天。记住：我习惯晚上读书。` 右侧应出现带来源的记忆。
2. 关闭程序再启动，问：`你还记得我读书的习惯吗？` 验证跨重启回忆。
3. 在记忆面板修改一条偏好，或点击“忘记”。再次询问，验证新信息生效。
4. 发消息：`今天成功了，真开心！` 观察心情与精力；发出需要关切的消息，观察另一种变化。
5. 在“提醒”页点击“20 秒后提醒我”。后台运行约 20 秒后，聊天中会出现带“约定提醒”标记的消息。
6. 测试关闭网页：先安排一个提醒，再关闭网页，保持 Python 程序运行；到时后重新打开，消息仍在。
7. 要测试自主闲聊，在“设定”中勾选“空闲时主动找我聊天”，将等待时间临时改为 1 分钟。测试完可改回 120 分钟或关闭。

默认免打扰为 UTC+8 的 **23:00–08:00**。测试时若正好处于免打扰时段，把开始与结束设为同一小时即可临时关闭免打扰。提醒表单的时间按浏览器本地时区解释；免打扰与每日闲聊上限按设定的 UTC 偏移解释。

## 功能与边界

### 长期记忆

- SQLite 保存聊天、记忆、情绪、人格设定及提醒。
- 演示模式用保守规则提取 `我叫…`、`我喜欢…`、`我不喜欢…`、`不要叫我…`、`记住：…`。
- 真实模式额外让模型提取最多三条值得保存的事实、偏好或经历。只接受当前用户消息里真实存在的原文片段；不直接保存模型改写的事实。模型仍可能误判原文含义，请在面板纠正。
- 名字和同一对象的明确喜好会更新已有记录。复杂矛盾、否定、转述和跨语言同义句的自动归并尚未实现。
- 每次检索按中文双字、英文关键词重合与资料类型排序，注入最多 10 条记忆和最近 16 条消息。第一版没有向量语义检索，也没有长对话自动摘要。
- 记忆可手动添加、修改、删除。修改/删除会让旧聊天退出模型短期上下文，移除相应来源消息的原文并清理重试缓存，防止旧回复再次强化错误信息。其他历史回复仍可能包含该事实；需要完整移除这些历史文本时，可再清空聊天记录。
- “清空聊天记录”保留长期记忆、情绪及任务。`导出我的数据`导出全部记录，不受页面最近 200 条消息的显示上限影响。

### 情绪状态

- `valence` 表示心情，`energy` 表示精力，范围均为 0–1。
- 由透明的关键词事件规则小幅更新，按六小时指数时间常数回归基线（心情 0.60，精力 0.65）。状态会持久化，并进入真实模型的提示背景。
- 这是可调试的情绪模拟，不是情感识别模型，也不证明主观感受。界面会说明最近的变化原因。
- 名字和人格可在“设定”修改，不会因为一轮聊天自动改写。

### 主动行为

- **明确提醒默认可用**：通过提醒表单安排，后台每两秒检查一次。
- **自主闲聊默认关闭**：可在设定中开启；空闲达到指定间隔后发起聊天，按本地日期限制每天数量。演示模式使用固定问候，真实模式由模型生成。
- 主动消息暂停开关与免打扰适用于所有自动投递。每日条数上限只限制自主闲聊，不限制明确提醒。
- 提醒消息与完成状态在同一 SQLite 事务内提交；跨重启及并发后台实例不会重复投递同一提醒。取消的提醒不再投递。
- 电脑休眠、关闭程序期间不会运行。程序恢复后补投到期提醒；处于免打扰期间则继续等待。
- 消息送到这个应用的聊天收件箱，**没有接入微信、QQ、邮件或手机推送**。关闭网页不影响后台写入；关闭 Python 程序则不再检查任务。
- 可主动点击“开启桌面通知”。仅在浏览器支持、获得通知权限、网页仍在后台打开时显示系统通知；网页完全关闭后没有系统通知。
- 第一版不从聊天里自动解析“明晚提醒我”等日期，避免错误安排；请使用明确的提醒表单。

## 代码与数据

```text
app.py             模型适配、SQLite、记忆、情绪、后台任务、HTTP API
static/index.html  中文聊天界面
static/style.css   响应式样式
static/app.js      聊天、轮询、通知、记忆与任务管理
tests/test_app.py  持久化、调度、纠错、HTTP 与模型协议测试
.env.example       模型配置示例
start.cmd          Windows 双击启动
start.ps1          PowerShell 启动
data/              首次启动时生成的私人数据库
```

为降低第一次运行的门槛，HTTP 层使用 Python 标准库，而不是需要额外安装的 FastAPI；业务逻辑集中在 `Engine`，后续可以迁移到 FastAPI。没有使用 Mem0，第一版的本地记忆机制可直接阅读与修改。

备份请先停止后台程序，再复制整个 `data/` 文件夹。`.env`、数据库和私人导出文件不应提交到 GitHub；项目已配置 `.gitignore` 忽略密钥和运行数据。它是本机单用户原型，未实现账号系统、多用户隔离、生产托管或数据库加密，不要直接暴露到公网。

运行测试（不调用真实模型、不需要密钥）：

```powershell
python -m unittest discover -s tests -v
```

模型协议测试使用本机模拟服务检验 Responses 与 Chat Completions 的请求和解析；真实服务需要你配置自己的凭据后验证。官方协议参考：[Responses 迁移与输出结构](https://developers.openai.com/api/docs/guides/migrate-to-responses)。

后续最值得加的三个能力：中文向量检索和可追溯摘要、日期解析后的提醒确认、语音输入输出。先保留现在的 SQLite 数据结构与来源信息，逐步替换检索和交互层即可。
